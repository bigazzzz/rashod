# Секреты через Mozilla SOPS (age)

Настройки Workers AI хранятся в [`cloudflare.enc.yaml`](../cloudflare.enc.yaml), остальные секреты — в [`secrets.enc.yaml`](../secrets.enc.yaml). Оба файла зашифрованы для одних и тех же получателей age.

## Ключи (разделены специально)

| Ключ | Куда | Зачем |
|------|------|--------|
| `keys/age-deploy.key` | **только сервер** | `deploy.sh` расшифровывает секреты |
| `keys/age-dev.key` | машина разработчика | правка `sops secrets.enc.yaml` |

Личный age-ключ для деплоя **не используется**. На сервер копируйте только `age-deploy.key`.

Публичные ключи прописаны в [`.sops.yaml`](../.sops.yaml).

## Что шифруем

| Переменная | Назначение |
|------------|------------|
| `CLOUDFLARE_ACCOUNT_ID` | идентификатор аккаунта Workers AI |
| `CLOUDFLARE_API_TOKEN` | токен Workers AI для генерации обложек |
| `OPS_TOKEN` | `/internal/ops/*` (только между контейнерами) |
| `ADMIN_PASSWORD` | пароль входа в `/admin` |
| `ADMIN_SESSION_SECRET` | подпись cookie-сессии админки (отдельный random) |

Публичные `DOMAIN`, `PUBLIC_BASE_URL`, … — в обычном `.env` (не в git).

## Редактирование (локально)

```bash
export SOPS_AGE_KEY_FILE=$PWD/keys/age-dev.key
sops secrets.enc.yaml
sops cloudflare.enc.yaml
```

Закоммитьте изменённые зашифрованные файлы.

## Деплой

Серверу нужны публичные настройки в `.env` и отдельный приватный ключ в
`keys/age-deploy.key` с правами 600. Другой путь можно указать в
`SOPS_AGE_KEY_FILE`. Подготовьте ключ через защищённый канал до первого
деплоя. При каждом запуске `deploy.sh` расшифровывает оба файла перед запуском Compose. Настройки Workers AI передаются через временный dotenv-файл с правами 600, который удаляется при выходе.

## Ротация после публикации ключа

1. Создайте новую пару age в защищённом месте. Установите новый приватный
   ключ на сервер рядом со старым до переключения деплоя.
2. Замените публичный recipient деплоя в `.sops.yaml`, сохранив recipient
   разработчика. Используйте доверенный ключ разработчика для
   команд `sops updatekeys` и `sops rotate -i` для каждого из двух зашифрованных файлов.
3. Выпустите новые учётные данные у внешних провайдеров и замените все
   защищённые значения, включая пароль админа, секрет подписи сессий и
   общий токен Ops. Вносите значения через редактор SOPS.
4. Проверьте расшифровку обновлённого файла новым ключом, переключите
   ключ деплоя и примените обновление. Отзовите старые учётные данные.
   Старые коммиты и клоны по-прежнему содержат прежний ключ и шифротекст.
